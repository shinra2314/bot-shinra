# Onix Discord Bot — Neon-редизайн и реорганизация

**Дата:** 2026-06-01
**Статус:** дизайн утверждён, готов к плану
**Подход:** A — поэтапно (бот остаётся рабочим между фазами), визуал-первым

## Цель

Полная реорганизация бота по четырём направлениям, заявленным пользователем:
1. **Визуал/картинки** — красивые canvas-карточки для всех осмысленных команд.
2. **Единый UI-дизайн** — одна визуальная система (dark neon / gaming) для карт и панелей.
3. **Структура кода** — разнести разросшиеся модули, навести порядок.
4. **Новые функции** — доработать механики поверх обновлённого визуала.

## Ограничения и способ верификации

- **Живого бота запустить нельзя** (нет токена/сервера). Верификация:
  - `npm run check` — синтаксис всех `.js`.
  - `scripts/render-sample-card.js` — рендер каждой карты в PNG, который Claude **смотрит глазами** и итеративно подкручивает. Скрипт будет расширен, чтобы рендерить весь каталог карт с фейковыми данными.
- Команды **не дефёрятся** (Components V2 несовместим с `deferReply`) → все билдеры карт укладываются в ~3с; загрузка аватаров остаётся с таймаутом (`loadRemoteImage`).
- Не смешивать классические embeds с Components V2 (discord.js отвергает).
- Русские пользовательские строки — оставить русскими.
- Музыку не трогаем (нет аудио-движка, по CLAUDE.md). Хранилище/SQLite-миграцию не трогаем.

## Фаза 0 — Неоновое ядро (фундамент)

### Палитра

```
Фон карт:      #0a0b14 → #06070d (линейный градиент) + неоновая сетка/скан-линии
Текст:         #F2F4FF (основной), #8A90B0 (приглушённый), #5A6080 (метки-капсы)
Неон-акценты по доменам:
  violet   #A855F7  профиль, основной
  cyan     #22D3EE  инфо, голос
  green    #34F5A0  успех, экономика, выигрыш
  red/pink #FF3B6B  казино, опасность, любовь
  gold     #FFD24A  монеты, топы
```

### Примитивы свечения (новый файл `src/services/canvas/primitives.js`)

`cardRenderer.js` разбивается: низкоуровневые примитивы выносятся в `canvas/primitives.js`, лейауты остаются/переезжают в `canvas/layouts/*`. Новые/обновлённые примитивы:

- `glowText(ctx, text, x, y, { color, blur })` — текст со свечением через `shadowBlur`/`shadowColor`.
- `neonStroke(ctx, pathFn, { color, blur, width })` — светящаяся обводка панелей/плиток (заменяет нынешнюю `rgba(255,255,255,0.06)`).
- `neonRing(ctx, cx, cy, r, ratio, color)` — кольцо прогресса с градиентом и свечением (апгрейд текущего `drawRing`).
- `gridBackground(ctx, w, h, { accent })` — фон: тёмный градиент + тонкая неоновая сетка + угловое радиальное свечение акцентом.
- `roundRect`, `drawAvatar`, `truncateToWidth`, `drawIcon` — переносятся как есть.

Существующие `paintHeroCard`/`paintProfileCard` переписываются поверх новых примитивов (тот же публичный контракт — команды не ломаются).

### Панели Components V2 (`src/ui/components.js`)

- `COLORS` → неоновые hex, выровненные с палитрой выше (используются как accent-цвет контейнера).
- `ICONS` остаются эмодзи (Discord не встраивает PNG в текст панелей), но проверяются на соответствие доменам.
- Хелперы (`panel`, `mediaPanel`, `bar`, `statGrid` и т.д.) — контракт сохраняется; при необходимости добавляются мелкие хелперы (напр. неоновый стиль `bar`).

## Фаза 1 — Каталог карт

`profileCard.js` превращается в **card kit**: набор билдеров поверх примитивов/лейаутов. Каждый билдер возвращает `{ files, imageUrl: 'attachment://card.png' }` (или imgenx-фоллбэк, если canvas недоступен). Команда цепляет карту через `mediaPanel({ imageUrl }) + reply(..., { files })`.

### Лейауты (в `src/services/canvas/layouts/`)

- **hero** (есть) — 1 аватар + 4 плитки. Используют баланс/timely.
- **profile** (есть) — identity-панель + чипы + статы 2×2 + достижения.
- **leaderboard** (новый) — вертикальный список топ-N: ранг/медаль, аватар, имя, значение. Для `/top`.
- **result** (новый) — крупный исход (казино/игра): ставка → результат, неон-вспышка цветом исхода.
- **clan** (новый) — герб/иконка, уровень, казна, состав, прогресс войны. Для `/clan`.
- **love** (новый) — парная карта: два аватара + сердце, дни вместе, совместимость. Для `/love`.
- **drop** (новый) — выпавший предмет крупно, редкость цветом рамки/свечения. Для `/case`.
- **grid** (новый) — сетка плиток-товаров. Для `/market` (магазин/инвентарь).

### Соответствие команда → карта

| Команда | Карта | Примечание |
|---|---|---|
| `/profile` | profile | редизайн в неон |
| баланс, timely | hero | редизайн в неон |
| `/top` | leaderboard | новый |
| `/casino` (слоты/рулетка/итог) | result | новый |
| `/clan` (обзор) | clan | новый |
| `/love` (профиль пары) | love | новый |
| `/case` (открытие) | drop | новый |
| `/games` (дуэль/итог) | result | переиспользует result |
| `/market` (магазин/инвентарь) | grid | новый |

Команды, где карта неуместна (короткие подтверждения, настройки, модерация-квитанции), остаются на неоновых текстовых панелях.

## Фаза 2 — Структура кода

- **Разнести `economy.js` (1008 строк)** по смыслу: баланс/перевод/timely остаются в `economy.js`; кейсы → `cases.js`; (магазин уже в `market.js`). Все модули сохраняют контракт `{ commands, handleComponent? }` и регистрируются через `commands/index.js`.
- **Роутер компонентов**: текущая цепочка `handleComponent` по модулям сохраняется (обратная совместимость), но добавляется явная карта префиксов `customId → модуль` для читаемости/диагностики дублей.
- **`cardRenderer.js`**: разбит на `canvas/primitives.js` + `canvas/layouts/*` (см. Фаза 0/1). `cardRenderer.js` остаётся фасадом с тем же экспортом.
- **`profileCard.js`**: становится card kit-фасадом; каталог кастомизации (`PROFILE_CATALOG`) при необходимости выносится в `profileCatalog.js`.

Каждый рефактор: сначала зелёный `npm run check`, затем рендер контрольных PNG — поведение не меняется.

## Фаза 3 — Новые/доработанные функции

Объём согласуется отдельно после Фаз 0–2 (зависит от того, что покажет визуал). Кандидаты, естественно ложащиеся на новый каталог карт:
- Топы по разным метрикам (монеты/голос/сообщения/уровень) с переключателем-селектом, рендер через leaderboard-карту.
- Расширение клан-войны/казны с визуализацией на clan-карте.
- Достижения с карточкой-уведомлением (drop-лейаут).

Этот раздел — backlog; конкретика фиксируется отдельной мини-спекой, чтобы не раздувать первый план.

## Изоляция и границы

- `canvas/primitives.js` — что: низкоуровневое рисование (свечение, фон, кольцо). Зависит: только от `@napi-rs/canvas`. Тестируется рендером PNG.
- `canvas/layouts/*` — что: каждый лейаут собирает одну карту из примитивов. Зависит: от примитивов + иконок. Один файл = один лейаут.
- `profileCard.js` (card kit) — что: маппинг доменных данных (профиль/клан/топ) в spec лейаута. Зависит: от layouts + `utils/format`. Не знает про canvas-детали.
- Командные модули — что: бизнес-логика + сбор данных + вызов билдера карты + ответ панелью. Зависит: от card kit + `ui/components`.

## Критерии готовности (по фазам)

- **Ф0:** `npm run check` зелёный; контрольные PNG старых карт (профиль/баланс/timely) перерисованы в неон и визуально одобрены.
- **Ф1:** каждая новая карта рендерится в PNG, визуально одобрена; команды подключены, `npm run check` зелёный.
- **Ф2:** модули разнесены, `commands/index.js` не падает на дублях, `npm run check` зелёный, поведение не изменилось (карты рендерятся идентично).
- **Ф3:** по отдельной мини-спеке.
