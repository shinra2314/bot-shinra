# Визуальный апгрейд команд бота — дизайн

**Дата:** 2026-05-31
**Статус:** утверждён к написанию плана

## Цель

Поднять визуальное качество всех команд бота до уровня референса (тёмная тема,
акцентные цвета, аватар с кольцом прогресса, плитки-статы, аккуратная
типографика). Работаем в двух слоях:

1. **Components v2 панели** — текстовые контейнеры Discord (balance, timely, shop,
   case, и все остальные). Улучшаем в рамках того, что рендерит Discord.
2. **Геройские карточки-картинки** — локальный рендер PNG через `@napi-rs/canvas`
   для профиля, баланса и результата timely.

Объём: **все 15 командных модулей**. Логику команд, тексты-строки (русский),
экономический баланс, схемы customId, БД и музыкальный движок **не трогаем** —
меняем только презентационный слой.

## Ограничения и факты (из разведки кода)

- `panel()` в `src/ui/components.js` используется всеми 15 модулями — улучшение
  одного файла поднимает все команды сразу.
- `imgenx` (внешний URL-рендер) умеет только `img:` и `txt:` слои над одним
  `fill`; нет box-примитива; жёсткий лимит URL 2000 символов (в `profileCard.js`
  уже есть fallback из-за него). Поэтому геройские карточки уходят на canvas.
- `sharp` в зависимостях **отсутствует** (в `package.json` только
  `better-sqlite3`, `discord.js`, `dotenv`). Заметка в `CLAUDE.md` про sharp —
  устаревшая. Добавляем `@napi-rs/canvas` (prebuilt-бинарь, без сборки).
- `componentPayload()` уже поддерживает `files` — карточку отдаём как
  `attachment://card.png`.
- **Баг:** `getProfileCardUrl` вызывается с `clan`, `rank`, `favoriteRoleNames`,
  но реализация их игнорирует. Чиним при переписывании на canvas.

## Архитектура — три изолированных слоя

### Слой 1: дизайн-система Components v2 (`src/ui/components.js`)

Расширяем без поломки обратной совместимости — существующие вызовы `panel()`
продолжают работать, просто выглядят чище.

- **Палитра:** добавить нейтральные тона и держать единый набор акцентов
  (`COLORS`). Карточный фон/акцент в одном месте.
- **Иконки доменов:** карта эмодзи на домен — 💰 экономика, 🎴 кейсы, 🏆 топы,
  🛡 модерация, 🎲 игры, 💞 love, 🎵 музыка, 👤 профиль. Подставляются в eyebrow/
  заголовок.
- **Новые хелперы:**
  - `statGrid(items)` — аккуратные пары «иконка/название → значение», выровненные.
  - `progressBar(value, max, width)` — текстовый бар `▰▰▰▱▱` + проценты.
  - `badge(label)` / `chip(label)` — инлайновые метки.
  - `keyValue(name, value, hint?)` — единый формат строки-факта.
- **Полировка `panel()`/`mediaPanel()`:** консистентные разделители, иконка в
  заголовке через `eyebrow`, аккуратные `footer` (`-#` стиль).

Контракт: чистые функции, возвращают строки/builder-ы. Без побочных эффектов.

### Слой 2: рендер карточек (`src/services/cardRenderer.js`)

Новый модуль. Единственная ответственность — превратить декларативный `spec` в
PNG-буфер.

- **API:** `async renderCard(spec) -> Buffer`. `spec`:
  ```
  {
    width, height,
    background: { type: 'gradient'|'solid', ... },
    avatar: { url, ring: { value, max, color } },
    title, subtitle,
    tiles: [ { label, value, accent? } ],   // плитки-статы
    badges: [ string ],
    accent
  }
  ```
- **Реализация:** `@napi-rs/canvas` — `createCanvas`, градиенты
  (`createLinearGradient`), скруглённые плитки (`roundRect`), кольцо прогресса
  (`arc`), аватар кружком (clip + `loadImage`), текст с зарегистрированным
  кириллическим шрифтом (`GlobalFonts.registerFromPath`).
- **Шрифт:** кладём `assets/fonts/Montserrat-*.ttf` (с поддержкой кириллицы) в
  репозиторий, регистрируем при загрузке модуля.
- **Иконки flaticon:** для плиток/декора карточек используем PNG-иконки с CDN
  flaticon (`https://cdn-icons-png.flaticon.com/...`), грузим через `loadImage`.
  Иконки кэшируем (один раз скачали — держим Buffer в памяти), на ошибку загрузки
  рендерим без иконки. В Components v2 панелях остаются unicode-эмодзи — Discord не
  встраивает произвольные картинки в текст.
- **Аватар:** грузим по URL пользователя; при ошибке — плейсхолдер-кружок, рендер
  не падает.
- **Изоляция/фолбэк:** фасад. Если `@napi-rs/canvas` недоступен (require кинул) —
  модуль логирует и сигналит вызывающему использовать imgenx-фолбэк, чтобы команды
  не падали.

### Слой 3: интеграция и раскатка

- `src/services/profileCard.js` → переписать поверх `cardRenderer`; наконец
  использовать `clan`/`rank`/`favoriteRoleNames`. Возвращает `{ attachment, name }`
  вместо URL (или fallback-URL, если canvas недоступен).
- `src/commands/profile.js` → отдавать карточку как файл-вложение.
- `src/commands/economy.js` → карточки для `balance` и результата `timely`;
  панели shop/case/give/transactions/inventory — на новые хелперы.
- Остальные модули (games, casino, love, clans, tops, roles, market, rooms,
  moderation, admin, music, fun, basic) → применить хелперы/иконки/единый тон.
  Только презентация, логика без изменений.

## Поэтапная поставка

Каждый этап самодостаточен и проверяется `npm run check`.

1. **Этап 1 — дизайн-система панелей.** `components.js` + раскатка по всем
   модулям. Видимый эффект во всех командах, ноль новых зависимостей.
2. **Этап 2 — геройские карточки.** Установка `@napi-rs/canvas`, шрифт,
   `cardRenderer.js`, переписать `profileCard.js`, карточки balance/timely.
3. **Этап 3 — финальная раскатка и согласование** оставшихся модулей,
   обновление устаревшей заметки про sharp в `CLAUDE.md`.

## Проверка

- `npm run check` после каждого этапа (единственный автотест — `node --check`).
- Ручная проверка рендера `cardRenderer` отдельным скриптом, сохраняющим PNG в
  файл для глазами-проверки (карточка выглядит как референс).
- Нет линтера/тестов — опираемся на синтаксис-чек и визуальную проверку PNG.

## Вне объёма (YAGNI)

- Не клонируем референс пиксель-в-пиксель — берём как образец стиля.
- Не меняем аудио-движок, БД, экономику, customId-схемы, тексты команд.
- Не добавляем линтер/тест-фреймворк.
